# 标准输出包与交付协议

## 1. 目标

每首诗完成后都交付一个可直接发布、可复核、可追溯、可再次编辑的版本化目录。发布者不需要从制作文件中寻找成片，后续制作者也能定位关键帧、H3 提示词、ChatCut 记录和验收证据。

最终包遵循四条原则：

1. **发布成品与制作归档分层。** 最终视频、封面和可复制文案永远在最浅层级；候选稿不进入发布成品。
2. **版本不可变。** 已交付的 `v01` 不被覆盖；修改后创建 `v02`。
3. **清单可核验。** 包含机器可读 `manifest.json`、人工可读清单和 `SHA256SUMS.txt`。
4. **缺件不冒充完成。** 任一必选项缺失时状态只能是 `INCOMPLETE`。

## 2. 标准目录

目录名：

```text
<诗名>_东方美学短片_<YYYY-MM-DD>_<vNN>/
```

目录结构：

```text
<输出包>/
├── 00-交付清单.md
├── manifest.json
├── SHA256SUMS.txt
├── 01-发布成品/
│   ├── 视频/
│   │   ├── <诗名>_3x4_1080p_<vNN>.mp4
│   │   └── <诗名>_3x4_1080p_无字版_<vNN>.mp4       # 可选
│   ├── 封面/
│   │   └── <诗名>_封面_3x4_<vNN>.png
│   └── 文案/
│       ├── 发布标题与正文.md
│       └── 发布文案-纯文本.txt
├── 02-内容依据/
│   ├── 原文与出处.md
│   ├── 意境与创作说明.md
│   └── 字幕与朗诵文本.md
├── 03-制作归档/
│   ├── 已确认关键帧/                              # 可选但推荐
│   ├── H3视频提示词/                              # 可选但推荐
│   ├── H3任务记录.md                              # 可选
│   └── ChatCut项目与导出记录.md                   # 可选但推荐
└── 04-质量验收/
    └── 最终验收.md
```

不要复制下列内容：失败候选图、失败视频、浏览器缓存、重复导出、临时截图、下载中的残缺文件、工具密钥或账号信息。

## 3. 必选内容

### 3.1 发布成品

- 一条最终 MP4；默认 1080×1440、30 fps、H.264、3:4；
- 一张最终 3:4 封面；默认 1080×1440 或同等 3:4 高分辨率；
- `发布标题与正文.md`：最终标题、备选标题、正文、置顶评论、话题标签、封面题字、出处说明；
- `发布文案-纯文本.txt`：去掉 Markdown 标记，可直接全选复制到发布平台。

### 3.2 内容依据

- 原文、作者、朝代、可靠出处和异文说明；
- 本片的意境理解与视觉转译，明确哪些是文学事实，哪些是创作推演；
- 成片实际使用的字幕、朗诵文字、停顿和重音。

### 3.3 验收与追踪

- 最终验收记录；
- 人工交付清单；
- 媒体元数据与文件路径清单；
- 全包文件 SHA-256 校验和。

## 4. 可选归档

只归档已批准且能帮助复现的内容：

- 已确认关键帧；
- 最终 H3 单行提示词、批量文件和上传顺序；
- H3 任务 ID、模型、模式、时长、分辨率和审核结论；
- ChatCut Project ID、Timeline ID、编辑器链接、导出记录；
- 无字版成片、SRT、备用封面或备用标题。

大型源素材可保留在原项目或云端，只在记录中写可定位的相对路径、项目 ID 或任务 ID；不要为了“完整”复制全部候选，造成交付包膨胀。

## 5. manifest.json

至少记录：

- `schema_version`、`package_id`、`status`、`version`、`created_at`；
- 诗名、作者、朝代、最终发布标题；
- 最终视频的相对路径、字节数、SHA-256、codec、宽高、fps、时长、音频流状态；
- 封面的相对路径、字节数、SHA-256、宽高和比例；
- 发布文案、原文出处、字幕朗诵和验收记录的相对路径；
- 每个已归档文件的相对路径、大小和 SHA-256；
- 机器检查与人工检查的结论。

包内路径一律使用相对路径。不要把私人绝对路径、登录信息、云端密钥写入 manifest。

## 6. 命名与版本规则

- 首次正式交付为 `v01`，修改依次为 `v02`、`v03`；
- 版本号必须同时出现在包名、成片名、封面名和 manifest；
- 文件名避免“最终版2”“真的最终版”等不稳定字样；
- 同一版本目录已存在时，打包程序必须停止，不自动删除或覆盖；
- 小修改也建立新版本，使发布文件和审查证据始终一一对应。

## 7. 自动组装

运行：

```bash
python3 scripts/build_release_package.py \
  --project-dir "/path/to/project" \
  --video "/path/to/final.mp4" \
  --cover "/path/to/cover.png" \
  --version v01
```

脚本默认从项目目录读取：

- `06-发布/标题与笔记.md`；
- `01-诗词与意境/原文与版本.md`；
- `01-诗词与意境/意境拆解.md`；
- `05-ChatCut/字幕与朗诵文本.md`；
- `06-发布/发布检查.md`；
- 已确认关键帧、H3 提示词、任务记录和 ChatCut 导出记录。

路径不同时用对应参数覆盖。脚本在全部必选输入存在且媒体规格正确后，复制文件、生成纯文本、写 manifest 和交付清单、计算校验和，并把项目状态更新为 `publish_ready`。

## 8. 交付前最终检查

- 从 `01-发布成品` 独立完成一次模拟发布：能找到视频、封面、标题和正文；
- 缩略图检查封面，手机尺寸仍能读出大标题；
- 播放本地成片，检查首帧、尾帧、音频和关键字幕；
- 对照原文检查诗句、作者、朝代和印章；
- 运行 SHA-256 校验；
- 随机打开制作归档中的一个关键帧、一个提示词文件和 ChatCut 记录；
- 确认包内没有失败候选、占位符、敏感信息或私人绝对路径。
