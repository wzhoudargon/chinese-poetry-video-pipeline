# 标准输出包与交付协议

## 1. 目标

每首诗完成后都维护一个可直接发布、可复核、可追溯、可再次编辑的当前交付目录。发布者不需要从制作文件中寻找成片，后续制作者也能定位关键帧、H3 提示词、ChatCut 记录和验收证据。

最终包遵循四条原则：

1. **发布成品与制作归档分层。** 最终视频、封面和可复制文案永远在最浅层级；候选稿不进入发布成品。
2. **当前包优先。** 默认原位更新一个当前交付包；是否另建版本由使用者和 Agent 根据留档、审计或并行交付需要共同判断，不强制每次修改都升版。
3. **清单可核验。** 包含机器可读 `manifest.json`、人工可读清单和 `SHA256SUMS.txt`。
4. **缺件不冒充完成。** 任一必选项缺失时状态只能是 `INCOMPLETE`。

## 2. 标准目录

目录名：

```text
<诗名>_东方美学短片_<YYYY-MM-DD>_<vNN>/
```

目录结构：

```text
<输出包>/
├── 00-交付清单.md
├── manifest.json
├── SHA256SUMS.txt
├── 01-发布成品/
│   ├── 视频/
│   │   ├── <诗名>_3x4_1080p_<vNN>.mp4
│   │   └── <诗名>_3x4_1080p_无字版_<vNN>.mp4       # 可选
│   ├── 封面/
│   │   └── <诗名>_封面_3x4_<vNN>.png
│   └── 文案/
│       ├── 发布标题与正文.md
│       └── 发布文案-纯文本.txt
├── 02-内容依据/
│   ├── 原文与出处.md
│   ├── 意境与创作说明.md
│   ├── 字幕与朗诵文本.md
│   └── 故事脚本.md                               # 长篇/全文项目
├── 03-制作归档/
│   ├── 已确认关键帧/                              # 可选但推荐
│   ├── H3视频提示词/                              # 可选但推荐
│   ├── H3任务记录.md                              # 可选
│   ├── 旁白/                                      # 使用人物化朗诵时可选但推荐
│   │   ├── 诗人声音设定.md
│   │   ├── 生成与质检记录.md
│   │   └── 已确认/                                # 只含最终分句与安全元数据
│   ├── 印章/                                     # 必选
│   │   ├── 设计与提示词.md
│   │   └── 已批准印章.png
│   └── ChatCut项目与导出记录.md                   # 可选但推荐
└── 04-质量验收/
    └── 最终验收.md
```

不要复制下列内容：失败候选图、失败视频、浏览器缓存、重复导出、临时截图、下载中的残缺文件、工具密钥或账号信息。

## 3. 必选内容

### 3.1 发布成品

- 一条最终 MP4；默认 1080×1440、30 fps、H.264、3:4；
- 一张最终 3:4 封面；默认 1080×1440 或同等 3:4 高分辨率；
- `发布标题与正文.md`：最终标题、备选标题、正文、置顶评论、话题标签、封面题字、出处说明；
- `发布文案-纯文本.txt`：只去掉 Markdown 标记，可直接全选复制到发布平台；不得删减正文内容。代码围栏本身可以去掉，但围栏内的一至两个完整提示词、交流问题、置顶评论和全部 `#话题标签` 必须保留。

### 3.2 内容依据

- 原文、作者、朝代、可靠出处和异文说明；
- 本片的意境理解与视觉转译，明确哪些是文学事实，哪些是创作推演；
- 成片实际使用的字幕、朗诵文字、停顿和重音。
- 使用人物化旁白时，记录声音人物卡、模型、非敏感参数、试听批准、最终分句与质检结论；明确这是创作性声音设计，不是历史声音复原。

### 3.3 验收与追踪

- 最终验收记录；
- 人工交付清单；
- 媒体元数据与文件路径清单；
- 全包文件 SHA-256 校验和。

### 3.4 最终验收的机器可读字段

在现有 `发布检查.md` 中补记以下字段，不新增审批系统。依据必须来自用户实际批准和真实听审；已有批准仍适用时直接引用，不为填写字段再问一次。这里只记录当前发布资产，失败候选留在各自的历史记录中。

```markdown
- 成品批准：APPROVED
- 批准依据：已有批准的日期、范围及可定位的记录
- 人工听审：PASS
- video_sha256：当前成片的64位校验和
- cover_sha256：当前封面的64位校验和
- seal_sha256：当前印章的64位校验和

## 验收结论

PASS。当前素材的画面、声音、文字与发布用途已确认。
```

仅无音轨的静默成片允许 `人工听审：N/A`，同时填写 `不适用原因` 并使用 `--allow-no-audio`。有音轨的成片仍需听审，即使只有音乐。脚本检查字段、校验和及媒体，不能判断批准证据是否真实，也不能代替听审。素材变化后重新核对批准范围和校验和，不能机械刷新哈希掩盖尚未批准的改动。

专属印章定稿和含完整生成提示词的设计说明必须入包；批准的生成原图可另作可选归档，未采用候选不进入包。长篇/全文项目还需已批准故事脚本。短片超过35秒不会自动变成长篇。

## 4. 可选归档

只归档已批准且能帮助复现的内容：

- 已确认关键帧；
- 最终 H3 单行提示词、批量文件和上传顺序；
- H3 任务 ID、模型、模式、时长、分辨率和审核结论；
- 已批准的诗人声音设定、最终朗诵分句、字幕时间元数据和音频质检记录；
- 专属印章的批准生成原图（定稿、设计说明与提示词已作为必选项归档）；
- ChatCut Project ID、Timeline ID、编辑器链接、导出记录；
- 无字版成片、SRT、备用封面或备用标题。

大型源素材可保留在原项目或云端，只在记录中写可定位的相对路径、项目 ID 或任务 ID；不要为了“完整”复制全部候选，造成交付包膨胀。失败试听、API Key、鉴权请求头、临时音频 URL、完整 HTTP 响应和 shell 历史一律不进入输出包。

## 5. manifest.json

至少记录：

- `schema_version`、`package_id`、`status`、`version`、`created_at`；
- 诗名、作者、朝代、最终发布标题；
- 最终视频的相对路径、字节数、SHA-256、codec、宽高、fps、时长、音频流状态；
- 封面的相对路径、字节数、SHA-256、宽高和比例；
- 发布文案、原文出处、字幕朗诵和验收记录的相对路径；
- 使用旁白时，可记录已确认音频、人物卡和质检报告的相对路径与校验和，但只记录模型和非敏感参数；
- 每个已归档文件的相对路径、大小和 SHA-256；
- 机器检查与人工检查的结论。

包内路径一律使用相对路径。不要把私人绝对路径、登录信息、云端密钥、鉴权头、环境变量值或临时下载 URL 写入 manifest。

## 6. 命名与更新方式

- 首次正式交付可使用 `v01` 作为交付标识；修正当前包时可以继续沿用该标识，不自动递增；
- 版本标识必须同时出现在包名、成片名、封面名和 manifest，保证同一交付包内部一致；
- 文件名避免“最终版2”“真的最终版”等不稳定字样；
- 默认只维护一个当前交付包。修正内容时，可用 `--replace-existing` 在完整重建并通过检查后原位替换；
- 只有用户明确要求保留历史、项目需要审计快照，或存在并行交付方案时，才另建 `v02`、`v03` 等目录；
- 不静默覆盖：Agent 必须先确认目标确实是当前包，再显式选择原位更新或另建版本。这里的确认可以来自用户当前指令和项目状态，不要求每次额外询问。

## 7. 自动组装

运行：

```bash
python3 scripts/build_release_package.py \
  --project-dir "/path/to/project" \
  --video "/path/to/final.mp4" \
  --cover "/path/to/cover.png" \
  --seal "/path/to/seal.png" \
  --seal-brief "/path/to/seal-brief.md" \
  --version v01
```

修正当前交付包并沿用同一目录时，保持原来的日期和版本标识，再显式加入：

```bash
  --replace-existing
```

可先在同一命令加入 `--check-only`，仅验证必选输入、最终批准、校验和与媒体，不写包或状态。长篇/全文用 `--story-script` 指定已批准脚本，或在状态中设置 `target.long_form` / `target.full_text`。

成片时长默认对照 `target.final_duration_seconds`（旧状态可使用 `verification.export_duration_seconds`），允许误差默认 1 秒，可用 `--duration-tolerance` 调整。若计划时长已被后来的成片批准取代，使用 `--expected-duration` 写入已经批准的实际时长；不要为了通过检查擅自更改目标或加速朗诵。没有时长依据时只验证时长为正，manifest 中目标记为 null，不宣称匹配某个预期时长。

构建会完整解码视频、封面及印章，准备好兼容现有格式的新状态后再替换当前目录。旧包备份保留到状态提交成功；写入失败会恢复旧包。突然断电等进程外中断后应检查隐藏的 `.replaced-*` 备份，不自行删除。若需保留历史快照，使用新的版本标识。

脚本默认从项目目录读取：

- `06-发布/标题与笔记.md`；
- `01-诗词与意境/原文与版本.md`；
- `01-诗词与意境/意境拆解.md`；
- `05-ChatCut/字幕与朗诵文本.md`；
- `06-发布/发布检查.md`；
- 已确认关键帧、H3 提示词、任务记录和 ChatCut 导出记录。
- `05-ChatCut/旁白/` 中已完成的人物卡、生成质检记录和 `已确认/` 音频（若使用人物化旁白）。

路径不同时用对应参数覆盖；印章优先读取 `artifacts.approved_seal_asset`，兼容旧状态的 `verification.seal_final`。视频兼容 `verification.export_file`。保留既有扁平目录，不为打包移动素材。已有 `99_交付包` 时默认在那里输出，否则使用 `07-标准输出包`。

脚本兼容 `verification` 列表和字典、`current_stage` 与 `stage`，保留现有下一步和无关证据；不会修改人工批准字段。最终批准、文件校验和、实际解码及必选输入都通过后，才写 manifest 并晋级 `publish_ready`。

## 8. 交付前最终检查

- 从 `01-发布成品` 独立完成一次模拟发布：能找到视频、封面、标题和正文；
- 将 `发布文案-纯文本.txt` 作为真实发布输入逐段核对：最终标题、完整正文、一至两个提示词、交流问题、置顶评论和全部话题标签均存在；不得只依赖文件存在、脚本退出码或校验和；
- 所有必选文字输入均不得含未勾选必选项；未完成的人工听审、读音确认或其他质量门必须使完整包构建失败，不能只检查 `最终验收.md`；
- 缩略图检查封面，手机尺寸先读到经典诗句，随后仍能辨认较小的诗名；
- 播放本地成片，检查首帧、尾帧、音频和关键字幕；
- 对照原文检查诗句、作者、朝代和印章；逐字核对印文及来源，确认使用的是已批准的专属 AI 印章资产而非通用红框章；
- 对照发音表完整听审旁白，检查身份、读音、停顿、削波与杂音；
- 运行 SHA-256 校验；
- 随机打开制作归档中的一个关键帧、一个提示词文件和 ChatCut 记录；
- 确认包内没有失败候选、失败试听、占位符、API Key、鉴权头、临时 URL、敏感信息或私人绝对路径。
