# MiniMax H3 图生视频与批量生产

## 适用范围

本规范是诗词视频 Skill 中的 MiniMax H3 提示词参考，不依赖 H3 Studio 程序。模式选择、首帧指令与声音字段分工可供采用相同输入协议的 H3 工作流复用；诗句原文、画外朗诵和闭唇要求属于诗词场景，不强加给对白、演唱或其他视频任务。第8节的一行一任务是现有批量上传器适配，不是模型通用输入要求。本文件不是覆盖 H3 全部模式的独立通用 Skill，也不声明已验证 H3 Studio 的实际提交链路。

## 1. 运行前确认

MiniMax 模型、WebUI 字段、时长、分辨率和计费会变化。提交前读取当前界面或官方说明，确认实际模型名、模式、时长、声音开关、分辨率与预计成本。不要仅依赖旧项目记录。

默认生产规格：

- 3:4 竖版，由参考图决定画幅；
- 源片段默认 8 秒，实际按取句、气口和支持的模型参数确定，前后留剪辑余量；
- 一条任务一个连续镜头；
- 通过后再做 2K/高分辨率再生成（若当前界面支持）；
- 画面内禁止文字，诗句、题名、作者和印章后期完成。

先确定声音路线和逐句时间预算，再定各段时长。下方八秒示例应替换为本段实际值；首尾帧时间标记与 `--duration-seconds` 必须一致。

## 2. 选择生成模式

### 批量单图视频

适合不同场景、不同构图的独立诗句片段。每张图是一个任务的 `Picture 1`，每行提示词依次应用到每张图片。

### 首尾帧视频（FL2VA）

适合同一空间、同一人物、相近构图之间的连续状态变化，例如盛放到凋零、年轻到年老、门外到门内。每个独立任务内首帧始终叫 `Picture 1`，尾帧叫 `Picture 2`；不要写全局图片编号、`Video 1` 或 `reference_image`。

如果两张图的机位、人物比例、空间几何或风格差异过大，不要让首尾帧模式承担“瞬间换片”；改用两个独立单图片段和剪辑切换。

## 3. 按入口选择提示词结构

规则来源：[用户使用手册](https://vrfi1sk8a0.feishu.cn/wiki/FIWjwgL33ipnkekzk30crmKUnIh)（用户提供的 PDF 第18—20页）与其链接的[开发者 Prompt 指南](https://vrfi1sk8a0.feishu.cn/wiki/Vztzwstuqi3MQKkxs8QcGmxinxe)。2026-09-15 核对了前者相关完整页面、后者第2—3节及第4.1节开头；未读到的后续对白细则不视为已验证。

用户端自然语言可按“素材用途＋核心创意＋画面过程”组织；以下为开源结构化路径，不把两种入口格式混作一套强制规则。先确认实际后端是否还会自动扩写，记录真正提交给模型的文本。

I2VA 单图首帧 instruction 必须在第一行，后空一行再写三个字段；不要在其前面添加时长、标题或中文说明。时长写入主体并在生成参数中设置。

### 单图任务

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

integrated_multimodal_description: [Shot 1] 八秒单一连续镜头，3:4竖版，严格从Picture 1开始。[稳定元素]。[镜头与动作的时间路径]。[人物/物体/风向/数量约束]。[可选画外音及停顿]。[禁止项]。

overall_soundscape: [画内环境声、距离、层次和时序]。

non_diegetic_music: [配乐设计；不需要时写 N/A]。
```

### 首尾帧任务

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot 1) aligns with the 8.00-second mark of the target video.

integrated_multimodal_description: [Shot 1] 八秒单一连续镜头，严格从Picture 1开始，并在结尾准确落入Picture 2。[连续变化路径、身份与几何约束、声音、禁止项]。

overall_soundscape: [画内声音]。

non_diegetic_music: [配乐或 N/A]。
```

字段名、`Picture`/`Shot` 标签和对齐句保留英文；正文可用中文，不强制英文。旧 `How the reference picture(s)...` 单图句式仅作历史兼容，新写 I2VA 使用上面的固定 instruction。

三个字段分工：`integrated_multimodal_description` 按时间线写画面、动作、说话人、台词及同步场景内声音；`overall_soundscape` 概括环境声、物理动作声和非语言人声；`non_diegetic_music` 写观众听到的背景配乐。同步细节与整体概括可以同时存在，但要求一致。`N/A` 禁止背景配乐，不等于禁止原生朗诵或画内乐器声。

## 4. 动作结构（八秒仅作示例）

常用结构：

- `00:00.000—00:00.800`：首帧余量。只保留呼吸、细风、流云、水纹、灯火等自然运动。
- `00:00.800—00:06.500`：完成唯一主要动作或状态变化。
- `00:06.500—00:08.000`：减速、收束、稳定，给剪辑留尾部余量。

最终成片通常取中间 4–6 秒，但以动作完整和诗句气口为准。不要为了固定时长切断一步、回首、落泪、开花或入画动作。

## 5. 动作书写规则

提示词必须回答：

- 人物从什么姿态开始；
- 连续完成几步、几次或多远；
- 手、脚、衣袖、系带、持物如何相连；
- 风从哪边来，所有柔性物体是否同向；
- 镜头固定、推、拉、摇、移中的哪一种，方向与总幅度是多少；
- 哪个物体可以动，哪些绝对不动；
- 最终停在哪里、朝向哪里、看向哪里。

一段只设一个主动作和一个从属环境动作。避免同时“固定镜头、快速推近、环绕、焦段变化”；避免“人物缓步行走”却不给路径或只让他迈一步后原地摆动。

当静帧中人物站在悬崖尖端、栏杆前或狭窄平台，没有安全路径时，不强制行走。改用衣袍、发带、云层、灯火、呼吸、抬杯、回首等可行运动。

## 6. 旁白与声音

### 推荐：后期统一旁白

独立 H3 任务可能难以保持完全相同的音色。默认让 H3 生成环境声，把全片旁白和音乐统一放在 ChatCut 或外部音频环节。此时：

- `overall_soundscape` 写清画内声音；
- `non_diegetic_music: N/A`，或只写临时配乐意图；
- 不在画面提示中要求人物张嘴。

使用 Seed Audio 做人物化诗歌朗诵时，按 [poetry-voice.md](poetry-voice.md) 先完成短试听审批，再生成最终分句音频。H3 提示词只保留与画面有因果关系的环境声，不重复生成另一套旁白。

### 原生旁白模式

用户明确需要 H3 生成声音时，每行完整重述同一说话人：年龄感、性别、音区、普通话、语速、录音距离、情绪边界，并始终使用相同说话人 ID，例如 `(S1)`。

```text
约00:01.000开始，(S1)以[语气] says in an off-screen voiceover: <d>[Chinese] 诗句</d> while all on-screen figures’ lips remain completely closed.
```

上述标签是已有工作流示例，仅在当前后端支持时沿用；不能声称用户手册已证明该标签的全部语法或隔离能力。

同时写出句内停顿、重音、结束时间和画面动作的对齐点。不要让不同片段用不同年龄、距离或朗诵腔。若声音仍机械或过快，先核对实际提交文本与时间预算；替换已选旁白路线需用户授权，不用整体慢放画面掩盖问题。

### 防止制作说明被念出

- 明确唯一画外朗诵者、实际朗诵原文与每句窗口；表演说明只保留必要的短指令。诗意解析、心理长篇解释和发音讲解留在设计文档。
- 在支持标签的后端，只有实际台词进入对白标签。逐字对照原文，检查标签外重复台词、漏句和窗口越界；不能仅凭标签存在判定声音合格。
- 禁止项明确为额外人声、唱腔或背景配乐，避免笼统“无对白／无声音”与已要求的朗诵冲突。保留所需物理声和画内乐器声。
- 中文制作指令不是错误；简短英文只能作为控制变量的可选对照试验，不能当作通用修复或防串读保证。
- 先生成代表片段，以转写辅助逐字对照，再连续听检开头、停顿及收尾，确认无多读、漏读、重复或念出说明后再扩批。文本、字段校验不能替代声音验收。
- 串读时保留任务 ID、实际提交文本及上游扩写记录，先定位问题，不能仅凭成片推断是某种语言或字段导致。

## 7. 负面约束要针对风险

通用禁止项只保留高价值部分：文字、字幕、UI、标志、水印、人物复制、肢体畸形、面部融化、软焦、涂抹、厚雾和碎片纹理。

再加入本幕高风险结构：

- 双人关系：视线偏移、遮挡目标、交换身份；
- 竹林：竹叶增殖、竹竿穿人、灯笼复制；
- 舟与水：船体沉没、倒影变成实体、岸线融化；
- 宫阙：柱列漂移、栏杆变形、雕花增殖、玉石变成实心灰石；
- 衣袍：系带凭空出现、与身体断开、风向冲突；
- 镜面/倒影：人物与倒影不同步或双重实体化。

## 8. 批量 WebUI 文件

准备三个东西：

1. 按 `01、02、03…` 排序的参考图；
2. 同序号的可读多行提示词文件；
3. 一份“每行一个完整任务”的批量提示词文本。

批量单图模式：图片数 = 提示词行数 = 任务数。

相邻首尾帧模式：若界面以相邻图片自动组成任务，通常任务数 = 图片数 − 1；生成前必须以当前界面实际显示为准。若界面不重叠配对，手动列出每组，不让提示词循环复用。

运行：

```bash
python3 scripts/build_h3_batch.py \
  --mode single \
  --images-dir path/to/images \
  --prompts-dir path/to/prompts \
  --output path/to/batch-prompts.txt
```

批量文本中的每个任务只能占一个物理行；脚本会把可读版本的换行压成空格，但保留内容。这是既有批量上传器的适配，不是指南原样排版；单条可读版本保留 instruction 后空行。确认上传器实际送出的格式，不为通过旧校验器改错源提示词。

脚本检查结构、编号、数量与字符上限，不验证语义、对白准确性或生成声音；这些必须按上面的原文对照与试听流程验收。

## 9. 云端提交与回收

提交前展示并确认：模型、模式、任务数、单段时长、分辨率、声音、预计成本。未经授权不点击付费生成。

每个任务记录：序号、参考图、提示词文件、任务 ID、提交时间、状态、输出文件、是否通过、失败原因、是否获准重试。网络失败或模型终态失败后不要静默改参数重提。

下载后按序号命名，逐段检查：

- 人物身份和数量；
- 建筑、道路、栏杆、桥、船等几何；
- 动作是否完整且不循环；
- 镜头是否遵守方向和幅度；
- 风向和柔性物体连接；
- 有无融化、抖动、碎纹、文字；
- 声音是否可用。

失败片段只重写该片段。不能用 ChatCut 的遮挡、变速或模糊去掩盖结构性生成错误。

单图批量默认按文件开头的镜头编号配对（如 `01`、`S01`），数量相等但编号不同会拒绝。已有文件名采用阶段前缀或其他命名时，先核对完整上传顺序，再使用 `--pair-by order`；不要为通过检查自动改名或补造缺失镜头。首尾帧模式沿用明确的 adjacent/pairs 关系。
