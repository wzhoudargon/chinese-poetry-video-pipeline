# 诗人人物化朗诵与 Seed Audio 工作流

## 1. 目标与边界

这一步不是给画面随便配一个“古风男声”，而是为本诗建立一个可解释、可复核、能与镜头节奏配合的朗诵人物。默认使用用户已经在本机配置好的 Seed Audio HTTP 接口与 `seed-audio-1.0`；也可以人工录制，但仍执行同一套人物设定、试听审批和质检。

历史上没有可供还原的诗人录音。成片只能称为“根据生平、写作处境和作品气质进行的人物化声音设计”，不得称为诗人真实声音、历史复原或声音克隆。

## 2. 先选声音路线，再按需写人物卡

在 H3 提交前确定：沿用已批准原声/H3原声、H3同步生声、独立配音、用户录音或不使用旁白。记录成片取句、易错字、逐句时间预算与画面余韵。独立配音可用已批准试听或试读估时；H3同步生声先预算、生成后实听回填。

已有声音经批准且符合本次范围时直接沿用，不重新推导声音人物或要求试听。新增人物化声音才进入下列步骤。

文字预设不保证随机重生成的说话人一致。当前脚本没有参考音频或声线 ID 输入；需要严格同声时优先复用已有录音，或另行核实支持音频参考的工具与授权，不用反复增加形容词代替身份锁定。

在生成任何付费音频前建立 `诗人声音设定.md`，明确分开三层：

1. **可核实事实**：创作时期、年龄区间（若可考）、身份、处境、地域经历、作品气质。每项附可靠来源或标注不确定。
2. **创作推断**：由事实推导出的年龄感、声区、声音重量、气息、录音距离、语速、情绪动作。使用“本片设定为”，不写成历史结论。
3. **审美美化**：清晰度、温润度、风霜感、胸腔共鸣、近讲或远讲、需要保留与需要抑制的瑕疵。

人物卡至少包含：

```markdown
# 诗人声音设定

## 可核实事实
- 事实、来源与不确定性：

## 本片创作推断
- 年龄感：
- 性别与声区：
- 音色重量：
- 呼吸与录音距离：
- 语速、停顿与句尾：
- 各句的情绪动作：

## 审美美化
- 保留：
- 美化：
- 禁止：年轻播音腔 / 新闻腔 / 舞台朗诵腔 / 故作磁性 / 耳语 / 过度苍老（按本诗修改）

## 发音表
| 词 | 拼音/声调 | 分词与重音 | 人工复核 |
|---|---|---|---|

## 试听范围与目标
- 正文：
- 目标时长：
- 句间停顿：
- 画面进入点与结束余韵：
```

不要把“中年、低沉、磁性、沧桑”复制给所有诗人。李白、李清照、苏轼、张继或辛弃疾的声线逻辑必须分别从作品时点与本片命题推导。

### 2.1 可选音色预设

用户要求复用已批准的诗歌朗读音色时，先读 [voice-presets.md](voice-presets.md)，再把所选预设的人物基底复制到当前项目的声音人物卡中。

- 预设只锁定相对稳定的声区、音色重量、发声支点、咬字方式与默认生成参数；诗人事实、作品处境、逐句情绪、发音表、停顿和时长仍须按本诗补全。
- 只有经过用户人工听审批准的试听才可进入预设目录；目录中只保存生成后的试听样音、非敏感参数和人物基底，不保存原始真人参考录音、API Key、请求头或临时下载地址。
- 纯文字条件生成的预设应明确标为“音色特征拟合”，不得写成声纹克隆、真人原声或诗人历史声音复原。
- 选择预设不等于批准全文付费生成；仍须执行本文件第 4 节的短试听与付费审批梯。
- 同一个预设不得机械套给所有男性诗人。若作品需要青年感、亲密低语、女性声线、衰老感或完全不同的地域与身份质地，应新建设定或选择其他预设。

## 3. 密钥与调用安全

接口固定为：

```text
POST https://openspeech.bytedance.com/api/v3/tts/create
model: seed-audio-1.0
```

Skill 内的生成脚本只允许从以下位置读取密钥：

1. 当前进程环境变量 `SEED_AUDIO_API_KEY`；
2. macOS 钥匙串服务 `codex-poetry-audio-api-key`。

不得增加 `--api-key` 命令行参数；不得把 Key 写入 Skill、项目、人物卡、提示词、shell 历史、任务记录、JSON、日志、manifest 或交付包；不得为了排错打印请求头。密钥缺失时停止，并请用户在本机完成配置，不要求用户在对话中粘贴。

响应中的 Base64 音频或两小时临时 URL 只用于立即保存本地音频；元数据不得保存临时 URL。`X-Tt-Logid` 与请求 UUID 可留在本地生成记录中用于排错，但不属于发布素材。

## 4. 付费生成审批梯

按以下顺序执行，不可直接整首批量生成：

1. 核定原文、成片取句、异读与发音表；
2. 写声音人物卡和逐句节奏表；
3. 用 `--dry-run` 检查最终请求体，不读取 Key、不调用接口；
4. 用户批准本次付费试听后，仅生成最能暴露年龄感、咬字和情绪的 1–2 句，通常 8–15 秒；
5. 进行机器质检和人工听审；
6. 若失败，只修改一个主要变量并重新试听；同一方向默认最多三次付费试听，仍不成立则回到人物卡或向用户确认；
7. 用户明确批准声线后，再按诗句或剪辑气口生成最终音频；
8. 以实际音频时长回填镜头表，再进入 ChatCut。

用户对端到端制作的授权不等于无限次数的付费试听。每次新增批量或改变模型、参考方式、输出规格前，说明任务数和预计成本。

## 5. 提示词结构

自然语言提示词依次写：人物身份与处境、音色、每句情绪动作、发声支点、咬字与发音表、时间与停顿、禁止项、唯一正文。

高价值写法：

- “成熟、克制，但使用正常近距离发声音量，绝不耳语”；
- “第一句目光由远及近，第二句悲意只压在声线里，不哭诉”；
- “句尾自然收住，不逐字等长，不为凑时长机械加速”；
- 指明易错字的拼音、声调、分词和相邻词边界；
- 用明确的正文边界控制朗读；边界内重复句以及恰好与题名相同的词句仍必须全部读出，边界外提示不读。

低价值写法：只写“有感情地朗诵”“古风磁性男声”“像诗人本人”。它们既不可执行，也容易得到年轻化或通用播音腔。

默认生成纯人声：无配乐、无环境音、无钟声、无混响。环境声与音乐放在剪辑阶段独立控制。除非用户明确提供并授权使用合法参考音频，本流程使用纯文本人物设定，不擅自克隆或模仿可识别真人。

## 6. 脚本调用

先预览，不产生费用：

```bash
python3 scripts/generate_poetry_audio.py \
  --persona-file "05-ChatCut/旁白/诗人声音设定.md" \
  --text-file "05-ChatCut/旁白/试听文本.txt" \
  --output "05-ChatCut/旁白/试听/01-试听.wav" \
  --dry-run
```

用户批准后才运行付费生成：

```bash
python3 scripts/generate_poetry_audio.py \
  --persona-file "05-ChatCut/旁白/诗人声音设定.md" \
  --text-file "05-ChatCut/旁白/试听文本.txt" \
  --output "05-ChatCut/旁白/试听/01-试听.wav" \
  --speech-rate -8 \
  --pitch-rate -2 \
  --confirm-paid-generation
```

参数只是起点，不应把同一组变速、音调和音量套给所有诗人。脚本默认拒绝覆盖已有文件；新试听使用递增编号，只有在用户明确要求时才用 `--overwrite`。

## 7. 双重质检

### 机器检查

运行：

```bash
python3 scripts/check_poetry_audio.py \
  --audio "05-ChatCut/旁白/试听/01-试听.wav" \
  --metadata "05-ChatCut/旁白/试听/01-试听.json" \
  --expected-text-file "05-ChatCut/旁白/试听文本.txt"
```

必须确认：

- 文件存在、可完整解码且只有预期音频流；
- 实际采样率匹配元数据、时长为正；字幕时间有效、有序并落在音频边界内。生成元数据标注 subtitle_time_unit，旧 Seed Audio 记录默认毫秒；未知单位应先核实；
- 返回字幕与正文内容一致；
- 没有削波；建议旁白原始/审听版 true peak 不高于 `-1 dBFS`；
- 未混音旁白的综合响度通常落在约 `-24` 到 `-14 LUFS`，超出时先检查原因，不机械归一化；
- 元数据中没有 Key、请求头或临时下载 URL。

机器检查不能证明诗词读音正确。独立 ASR 可辅助发现漏字、错序和明显误读，但同音字、古音、异读、专名必须人工复核。

### 人工听审

至少完整听两遍：一遍只听人物和情绪，一遍对照正文与发音表。检查：年龄感、身份感、音色是否过度美化、是否年轻化、是否播音腔、停顿是否人机、重音是否与诗意冲突、字音与吞音、句首句尾、呼吸、爆音、齿音、混响、底噪和结尾余韵。

若原始音频本身削波、误读或人物不成立，重新生成；不要用降调、拉长、厚混响或强降噪把失败表演伪装成成品。

## 8. 原始文件、审听版与最终分句

- 原始返回文件只读保留，不覆盖；
- 为听审做的增益、限幅、裁静音另存为 `review`，并记录处理链；
- 只有用户批准的声线进入 `已确认/`；失败试听留在制作区，不进入标准输出包；
- 先根据声线保持能力选择连续录制后切分，或以支持身份锁定的方式按气口生成；独立文本任务可能改变音色，不能机械逐句拆生成；
- 每段记录：正文、人物卡版本、参数、实际时长、字幕、人工结论和对应镜头。

不要用时间拉伸解决朗诵节奏。若只是文件首尾有已验证静音，可无损裁剪；若发声本身过快或过慢，重新生成该句。

## 9. 与画面同步

建立一张唯一同步表：

| 段 | 正文 | 音频文件 | 实际时长 | 镜头可用区间 | 入点 | 句内动作 | 尾部余韵 |
|---|---|---|---:|---|---:|---|---:|

先按朗诵气口确定最终镜头取段，再做书法文字与印章。画面动作不能在句意尚未落下前提前结束；句末至少保留短暂视觉余韵。若 H3 原声含不一致旁白，静音或分离人声，只保留因果正确的环境声。

## 10. 完成证据

`voice_approved` 阶段至少需要：

- 完成的人物卡与发音表；
- 用户批准的短试听及批准记录；
- 最终分句 WAV、字幕/时间元数据和同步表；
- 机器检查报告与人工听审结论；
- 明确记录模型和非敏感参数；
- 证明项目、日志、manifest 和交付包中没有凭据。

若本片有意不用朗诵，记录“不适用”及替代声场设计，不伪造 `voice_approved` 文件。
